# Projects in a Space Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Space lists projects (name + folder); a new terminal starts in one, chosen from a picker or taken from the sidebar folder it is opened in; the sidebar shows a terminal's project.

**Architecture:** All rules are pure functions on `Space` in `SingularityCore` (new `Model/Project.swift`), unit-tested. `AppState` asks Core for a plan (start here, or ask), and "ask" is a new mode of the existing command palette. The sidebar and Edit Space only draw what Core answers.

**Tech Stack:** Swift, SwiftUI, Swift Testing. No new dependency.

**Spec:** `docs/superpowers/specs/2026-11-11-projects-design.md`

## Global Constraints

- Every new field in `space.json` is optional when decoding; files written before it load unchanged.
- An id that matches no project in the Space counts as nil, everywhere.
- Paths under the home folder are stored as `~/…`.
- A Space with no projects never shows the picker and starts terminals in `Space.workingDirectory`.
- The code and the interface keep saying "Folder".
- No SwiftUI `.help()` on chrome in the title-bar strip (CLAUDE.md); the sidebar is not in that strip.
- Never launch or activate a test copy of the app; verify with tests. Run tests with `scripts/test.sh`.
- Comment the non-obvious Swift; plain wording.

## Review Focus

1. A project is removed while folders, terminals and "last used" still point at it: they must behave as "no project" (no tag, folder asks again), never crash or show a stale name. Test: Task 1, `removingAProjectScrubsEverything` and `danglingIDsCountAsNil`.
2. Folders whose parent is missing or that form a cycle in a damaged `space.json`: the effective project lookup must end. Test: Task 1, `effectiveProjectSurvivesBrokenTree`.
3. The selected tab's `folderID` names a folder that no longer exists: the new terminal lands in Tabs, not in a ghost folder. Test: Task 1, `ghostFolderMeansNoFolder`.
4. A project added with an empty or whitespace name, or two projects with the same name or path: the name falls back to the folder's last path component; duplicates are kept and both work (ids differ). Test: Task 1, `emptyNameFallsBackToFolderName`.
5. The picker with a query that matches nothing: no rows, Return does nothing, Escape closes, no terminal opens. Test: Task 2, `pickerWithNoMatchOpensNothing`.

```swift
public struct Project: Codable, Hashable, Identifiable, Sendable {
    public var id: UUID; public var name: String; public var path: String   // path with "~" unexpanded
    public init(id: UUID = UUID(), name: String, path: String)
    /// Trimmed name, or the path's last component when that is empty ("~" → "Home").
    public var displayName: String { get }
}
// Space: var projects: [Project] = [], var lastProjectID: UUID? = nil
// Folder: var projectID: UUID? = nil        BrowserTab: var projectID: UUID? = nil

/// What New Terminal should do.
public enum TerminalStart: Equatable, Sendable {
    case start(directory: String, projectID: UUID?)
    case ask
}
public struct ProjectChoice: Equatable, Identifiable, Sendable {
    public var projectID: UUID?      // nil = the Space folder
    public var name: String          // project displayName, or "Space folder"
    public var path: String
    public var id: String            // projectID's uuidString, or "space-folder"
}

extension Space {
    public func project(_ id: UUID?) -> Project?
    /// The folder's own project (shown on its header); nil when unset or dangling.
    public func ownProject(ofFolder id: UUID?) -> Project?
    /// Own project, else the nearest enclosing folder's. Cycle-safe.
    public func effectiveProject(ofFolder id: UUID?) -> Project?
    /// The folder a new terminal lands in: the selected tab's folder, if that folder exists.
    public var folderForNewTerminal: UUID? { get }
    /// `folderID` nil = not in a folder. No projects → .start(workingDirectory, nil), also with alwaysAsk.
    public func terminalStart(inFolder folderID: UUID?, alwaysAsk: Bool) -> TerminalStart
    /// Split rule: beside-terminal's project, else its folder's effective project, else Space folder.
    public func splitTerminalStart(beside tabID: UUID) -> (directory: String, projectID: UUID?)
    /// Last used first, the rest in `projects` order, then the Space folder.
    public var projectChoices: [ProjectChoice] { get }
    /// Appends a terminal tab (selected, placed in `folderID` if that folder exists, else Tabs). Returns its id.
    @discardableResult
    public mutating func addTerminal(directory: String, projectID: UUID?, inFolder folderID: UUID?, select: Bool) -> UUID
    /// A choice made in the picker. A real project becomes `lastProjectID`; when `adoptForFolder`
    /// names a folder with no effective project, it also becomes that folder's project.
    public mutating func recordPickerChoice(_ projectID: UUID?, adoptForFolder folderID: UUID?)
    public mutating func setFolderProject(_ folderID: UUID, _ projectID: UUID?)
    /// Replaces the list; ids that are gone are cleared from folders, tabs and lastProjectID.
    public mutating func setProjects(_ projects: [Project])
    /// The project name for any terminal that has one (tooltips, list_tabs).
    public func projectName(of tab: BrowserTab) -> String?
    /// The sidebar tag: `projectName` only when the tab is in no folder, or its folder's effective project differs.
    public func projectTag(of tab: BrowserTab) -> String?
}
```

- [ ] **Step 1: Write the failing tests** in `ProjectTests.swift` (`@Suite struct ProjectTests`). A helper builds a Space "Work" with `workingDirectory: "~/Developer"`, projects web (`~/Developer/acme-web`) and docs (`~/Developer/acme-docs`), folder `task` (project web), folder `inner` inside `task` (no project), folder `loose` (no project). Tests and what they assert:
  - `oldFilesStillLoad`: JSON for a Space, a Folder and a terminal tab without the new keys decodes with `projects == []`, `lastProjectID == nil`, `projectID == nil`; a round trip keeps the new fields.
  - `effectiveProject`: `task` → web; `inner` → web; `loose` → nil; `ownProject(ofFolder: inner) == nil`.
  - `effectiveProjectSurvivesBrokenTree`: two folders that are each other's parent, and a folder whose parent id is unknown → nil, returns.
  - `terminalStartTable`: no projects → `.start("~/Developer", nil)` for every folder and for `alwaysAsk: true`; in `task` and `inner` → `.start("~/Developer/acme-web", web.id)`; in `loose` → `.ask`; no folder → `.ask`; `alwaysAsk` in `task` → `.ask`.
  - `ghostFolderMeansNoFolder`: selected tab with an unknown `folderID` → `folderForNewTerminal == nil`; `addTerminal(inFolder: unknown)` gives a tab with `folderID == nil`.
  - `addTerminalPlacesAndSelects`: in `task` the tab has `folderID == task.id`, `isPinned == false`, `projectID`, the directory, and is selected; with `select: false` the selection is unchanged.
  - `pickerOrder`: with `lastProjectID = docs` → names `["acme-docs", "acme-web", "Space folder"]`, last path `"~/Developer"`; with nil or a dangling id → web, docs, Space folder.
  - `recordPickerChoice`: a project sets `lastProjectID`; nil leaves it; `adoptForFolder: loose` sets `loose.projectID`; `adoptForFolder: inner` (inherits web) and `adoptForFolder: task` change nothing on the folders; nil choice adopts nothing.
  - `splitRule`: beside a terminal with project docs inside `task` → docs; beside a web tab in `task` → web; beside a terminal without project in Tabs → `("~/Developer", nil)`; beside a terminal without project in `task` → Space folder (spec: "beside a terminal with no project it is the Space folder").
  - `tagRule`: terminal(web) in `task` → nil; terminal(docs) in `task` → "acme-docs"; terminal(web) in Tabs → "acme-web"; terminal(web) in `loose` → "acme-web"; terminal without project → nil; a web tab → nil; `projectName` is non-nil for the first case.
  - `removingAProjectScrubsEverything`: `setProjects([docs])` clears `task.projectID`, the tabs' `projectID` and a `lastProjectID` of web; docs references stay.
  - `danglingIDsCountAsNil`: ids set by hand to an unknown UUID → `project`, `effectiveProject`, `projectTag` nil; `terminalStart` in that folder → `.ask`.
  - `emptyNameFallsBackToFolderName`: `Project(name: "  ", path: "~/Developer/acme-web").displayName == "acme-web"`; path `"~"` → "Home"; two projects with the same name both appear in `projectChoices`.


Behaviour: the three `openTerminal…` functions call `terminalStart`; `.start` adds the terminal (`addTerminal`, then `loadSelectedTab()`), `.ask` sets `palette = .newTerminalIn(folderID:adoptForFolder:)` through `showPalette`. `adoptForFolder` is true only for plain New Terminal inside a folder. `startTerminal` calls `recordPickerChoice` then `addTerminal`. `openTerminalInSplit` uses `splitTerminalStart` and sets the tab's `projectID`; placement unchanged.

`PaletteResults.items` for `.newTerminalIn`: one row per `space.projectChoices` (id `project-<choice.id>`, title name, subtitle path, hint "Last used" on a first row that is `lastProjectID` else "", icon `folder`, action `.run { startTerminal… }`). Empty query: that order. Otherwise only rows whose name or path fuzzy-match with the palette's existing threshold, best first. No URL or search row in this mode. Placeholder: "New terminal in…". The normal palette gains the command "New Terminal in…" (`cmd-new-terminal-in`) only when the Space has projects. `Commands.swift`: "New Terminal in…" with ⇧⌥⌘T under New Terminal.

`listTabs`: `entry["project"] = name` for a terminal with `space.projectName(of:)`.
