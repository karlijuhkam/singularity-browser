# Updates and Going Public Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One command on the owner's Mac publishes a release to a public GitHub repository, and the installed app updates itself from it with Sparkle.

**Architecture:** Sparkle 2 is linked into the app but only started in bundles that `release.sh` stamped with a feed URL and public key. The rule "may this copy update?" is a pure function in Core. `release.sh <version>` bumps, builds, signs, writes a one-entry `appcast.xml`, and publishes zip + appcast as one GitHub release (draft first). The feed URL is GitHub's `releases/latest/download/appcast.xml`.

**Tech Stack:** Swift 6 / SwiftPM, Sparkle 2.10.1 (binary XCFramework), bash, `gh`, `codesign`, `notarytool`.

**Spec:** `docs/superpowers/specs/2026-11-12-updates-design.md`. Read it first; this plan argues from it.

## Global Constraints

- Read `CLAUDE.md` first. Builds need `source scripts/env.sh`; tests run with `scripts/test.sh`.
- **The owner's daily copy runs from `build/Singularity.app`.** Never run plain `scripts/build-app.sh` or `scripts/run.sh`, never quit it. Build bundles with `APP=/private/tmp/sg-app/Singularity.app scripts/build-app.sh`.
- **A test copy must never be activated or sent keyboard/mouse input.** A bare binary activates itself on launch, so verify by app tests, by process checks (`pgrep`, exit codes, logs) and `screencapture -l <window id>` of an inactive window. What cannot be exercised that way goes on the owner's hands-on list (Task 9).
- Never click or run Connect/Update, never run the real `claude mcp add/remove` or `codex mcp add/remove`, never write `~/.claude.json` or `~/.codex/config.toml`.
- Never change the bundle ID `dev.roosa.Singularity`. Signing team is `T748B76PPL` only.
- Sparkle is pinned with `exact: "2.10.1"`. Check any Sparkle API or tool flag against the checkout's headers or `-h` before using it. Tools live in `.build/artifacts/sparkle/Sparkle/bin/` (`generate_keys`, `sign_update`).
- `Info.plist` keys, exact names: `SUFeedURL`, `SUPublicEDKey`, `SUEnableAutomaticChecks`, `SUScheduledCheckInterval`, `SUAllowsAutomaticUpdates`. The scratch-test key is ours: `SGUpdateTestBundle`.
- Feed URL: `https://github.com/karlijuhkam/singularity-browser/releases/latest/download/appcast.xml`.
- No secrets in the repository: no private key, no certificate, no notary password. Nothing personal beyond what the spec lists as accepted.
- **Stop points (wait for the owner's go):** creating the update key, making the repository public, publishing the first release, installing into `/Applications`. These are Tasks 8 and 9; Tasks 1 to 7 need no owner input.
- Boring, readable Swift; comment the non-obvious AppKit/Sparkle parts. UI copy is plain and short.
- Commit after each task. End commit messages with the session attribution line in use.

## Review Focus

Conditions the spec implies that are most likely to bite, each pinned by a test in the named task:

1. **A copy with `SINGULARITY_HOME` set, or a debug/test bundle, tries to update.** Expected: no updater object exists at all. → Task 2 (policy table), Task 3 (`AppState` test).
2. **The release command is interrupted or given bad input** (dirty tree, version not higher, tag taken, no key, empty notes). Expected: it stops before changing anything, or restores `Info.plist`. → Task 6 (`scripts/test-release.sh`).
3. **A release exists half-made on GitHub** (draft left by a failed run). Expected: the next run of the same version reuses or replaces the draft; installed copies never saw it. → Task 6.
4. **An agent calls the launcher while the app is closed or mid-update, with several bundles of the same ID on disk.** Expected: it starts the bundle it lives in, never another; mid-update it waits. → Task 4.
5. **The owner cancels the quit prompt (busy terminal) during an update, or the feed is unreachable.** Expected: the app keeps running, nothing is half-installed, no error window for a background check. → Task 7 (scratch update run) and the hands-on list in Task 9.

### Task 6: The release command

**Files:**
- Modify: `scripts/release.sh`, `scripts/test.sh`
- Create: `scripts/lib/version.sh`, `scripts/appcast.sh`, `scripts/test-release.sh`

**Interfaces:**

No `sparkle:channel` element.
- `scripts/release.sh`:
  - `release.sh <version> [--notes-file <path>]`: the full release.
  - `release.sh --skip-notarize`: as today (no version change, not stamped, nothing published, `dist/Singularity.app` kept).
  - `release.sh <version> --scratch <dir>`: for Task 7. Stamps `SUFeedURL=$SCRATCH_FEED_URL`, `SUPublicEDKey=$SCRATCH_PUBLIC_KEY` and `SGUpdateTestBundle` true, signs the zip with `$SCRATCH_KEY_FILE`, writes `<dir>/Singularity-<version>.zip`, `<dir>/appcast.xml` and leaves `<dir>/Singularity.app`. Skips every check and step that touches git, GitHub, the keychain key or notarization, and **does not change `Resources/Info.plist`** (it stamps the version into the bundle's copy).
  - Top of file, constants: `REPO="karlijuhkam/singularity-browser"`, `FEED_URL="https://github.com/$REPO/releases/latest/download/appcast.xml"`, `PUBLIC_ED_KEY=""` (filled in Task 8; the script refuses a full release while it is empty).

Order of the full release, as in the spec's section 4:

1. Checks before anything changes: `valid_version`; on `main`; clean tree; `git fetch` and `HEAD == origin/main`; `version_gt <new> <current>`; no tag `v<version>` locally or on origin; `gh auth status`; `PUBLIC_ED_KEY` set and `generate_keys -p` (check the flag with `-h`) prints the same key; a `T748B76PPL` signing identity exists. If a **draft** release `v<version>` already exists, delete it (`gh release delete --yes`, drafts only; a published one is an error).
2. `scripts/test.sh`.
3. Bump `CFBundleShortVersionString` to the version and `CFBundleVersion` by one. `trap` restores `Info.plist` (`git checkout -- Resources/Info.plist`) on any failure until step 7 succeeds.
4. Build, assemble, stamp `SUFeedURL` + `SUPublicEDKey` into the **bundle's** `Info.plist` with `PlistBuddy` before signing, embed Sparkle, sign. Notarize and staple when a `Developer ID Application` identity of the team exists **and** `xcrun notarytool history --keychain-profile "$NOTARY_PROFILE"` succeeds; otherwise sign with the team's `Apple Development` identity and set `NOT_NOTARIZED=1`.
5. Zip with `ditto -c -k --keepParent` to `dist/Singularity-<version>.zip`; `sign_update` the zip (parse `sparkle:edSignature="…"` and `length="…"` from its output); remove `dist/Singularity.app`.
6. Notes: without `--notes-file`, write `git log --format='%s' <previous tag>..HEAD` (all commits when there is no tag) to a temp file and open `${EDITOR:-vi}`; an empty result aborts. With `NOT_NOTARIZED`, put this line first: "Not notarized: works on the developer's Mac; Gatekeeper stops it elsewhere." Then `appcast.sh` with `--url https://github.com/$REPO/releases/download/v<version>/Singularity-<version>.zip`.
7. `git commit -am "Release <version>"`, `git push origin main` (no tag).
8. `gh release create v<version> --draft --target <commit sha> --title "Singularity <version>" --notes-file …`, upload the zip and `appcast.xml`, then `gh release edit v<version> --draft=false --latest`.
9. `git fetch --tags`; print the release URL. After a failure past step 7, print which numbered step to repeat by hand.
